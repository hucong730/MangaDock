# ADR 0002：Outline 与 Script 数据契约

- 状态：已接受
- 日期：2026-10-30

## 背景

阶段二需要让 LLM 产出可校验、可持久化、可并行生成并可直接供前端阅读的改编大纲和分集剧本。两个资产既要保持各自独立，又必须维持角色、顺序和时长的一致性。

## 决策

### Outline

Outline 包含 `synopsis`、`cast`、`episode_beat` 和 `asset_list`。角色记录统一名称、身份和 0 到 1 的戏份权重；每集记录梗概、爽点类型和 1 到 5 的强度。强度 5 定义为大爆点，validator 要求相邻大爆点间隔不超过 8 集，集号从 1 连续排列。

### Script 保存 cast 快照

Script 在 `episodes` 之外保存 Outline 的 `cast` 快照。这样 Script 可以独立校验每条台词是否属于已知角色，不需要在读取时回查 Outline 或数据库。代价是少量角色数据重复；如果后续需要角色设定版本化，应显式记录版本而不是隐式共享引用。

### 动作与台词使用 order 交错

每场分别保存 `action_beats` 和 `lines`，但每个元素都有 `order`。validator 要求 order 从 1 连续、动作开头、动作与台词严格交替。该结构兼顾按类型处理和真实阅读顺序，避免两个独立数组无法表达交错的问题。

### 时长由系统重算

`estimated_duration_s` 不信任 LLM 提交值。Episode validator 统计全部台词中的中文汉字，按 `ceil(汉字数 / 4.5)` 重算；标点、动作和标题不计时，零台词允许为 0。这样时长规则可测试且不会因模型算术偏差而失效。

## 备选方案

- Script 只保存 Outline ID：减少重复，但无法独立校验，也会增加读取耦合。
- 使用统一的 scene content 联合数组：能直接表达顺序，但动作与台词分别批量处理、前端组件和 schema 校验更复杂。
- 信任模型估算时长：实现更简单，但不可重复验证，容易与文本不一致。

## 影响

- 所有模型生成结果必须通过 Pydantic 校验，Fake Provider 也走同一路径。
- 并行生成以 Episode 为边界，汇总时按集号排序并再次校验完整 Script。
- 修改 cast、交错或时长规则属于数据契约变更，必须同步更新 schema、Prompt、测试、前端和本 ADR。
